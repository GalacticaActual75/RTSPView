# RTSPView 1.0.46-beta.1

Based on Stable 1.0.45. Settings remain schema 16.

## Audit fixes

- **F1:** Damaged update-monitor caches no longer prevent Controller startup. Checks cover malformed JSON, null entries and invalid versions/channels.
- **F2:** Native stream saves merge edited streams with current settings and reject same-stream conflicts. Settings writes coordinate across processes, including import/connector rollback and recovery. Standard and automation layout drafts carry revisions and reject stale saves.
- **F3:** Weather-only changes no longer invalidate the automation configuration hash or reset MQTT detection episodes.
- **F4:** Forgotten-password recovery preserves the encryption key ring used by MQTT and Tapo; reset administrator sessions and re-pair the connector. The README includes the separate compromised-key recovery case.
- **F5:** Exponential reconnect delays now reach the selected 5–300 second maximum. Jitter stays within that limit.
- **F6:** Release checks use one fail-fast runner. Pull requests run verification without release side effects. Restore, build, test and publish failures stop publication.
- **F7:** Invisible composited video skips frame uploads while decoding remains warm. Diagnostics identifies configured, hidden and original-overlay-source players. The local capacity matrix covers 1/9/16 main sources with 0/2/16 overlays, visible and hidden.
- **F8:** Snapshot capture uses a separate command channel, coalesces duplicate requests, and includes queue time in its timeout. A stalled capture regression verifies prompt automation delivery.

## Usability

Save & apply, Apply changes, Apply to wall and Use in layout draft explain their scope. Camera Weather Widgets explicitly apply across layouts and list saved layout usage. Numeric inputs complement placement and appearance sliders. Validation opens hidden fields and retains keyboard focus; dependency errors link to the blocking rules, layouts or overlays.

Browser and native weather agree on day/night icons, location-local future forecast dates, missing readings and Details hidden indicators. Rare streaming, recovery and image transform settings use Advanced sections. Empty states distinguish missing sources, unassigned streams, paused Viewer, unfetched weather and disabled integrations. Unexpected failures provide a short reference and the relevant Settings panel.

## Validation and limits

Release build: zero warnings and errors. Eleven C# check programs, fifteen JavaScript checks and three PowerShell checks passed locally, including real Controller HTTP, local MQTT and native fixture decoding. The synthetic capacity matrix passed all 18 cases with zero hidden-frame uploads and all expected players advancing. At the largest 48-player case, measured process working set was about 1.5 GiB; results include process/WPF caches from sequential cases and are workload- and host-specific, not recommended RTSP capacity. The [matrix results](1.0.46-beta.1-capacity.csv) record the single local run.

The capacity harness uses local 640×360 software-decoded video for all sources, including main tiles. It opens no RTSP connections and does not qualify hardware decoding, camera connection limits or sustained production workloads. Shared decoding is not included. Physical Tapo devices, production cameras, installer upgrades and GPU temperature hardware still require field validation.

Browser checks covered desktop and 390-pixel phone layouts, numeric weather placement, validation focus, and 44-pixel weather control targets without horizontal overflow. This is not a full screen-reader or physical touch-device qualification.

## Recovery

Install over 1.0.45 to retain settings. Back up the private data directory before upgrading. Returning to 1.0.45 does not require a schema conversion; when returning to pre-weather 1.0.44, follow the README instructions for settings.json.before-weather.json. Do not remove data-protection during an ordinary administrator-password reset.
