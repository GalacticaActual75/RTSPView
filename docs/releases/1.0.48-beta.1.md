# RTSPView 1.0.48-beta.1

This beta starts from Stable 1.0.47, including every change through 1.0.47-beta.26. It adds dashboard consistency fixes and the updater needed for future small application patches. Stable remains 1.0.47.

## Dashboard fixes

- Correct Display settings spacing and keep monitor selection, identification and help together.
- Use consistent rounded cards, borders and spacing across settings, diagnostics, stream inventory and plugin panels; maintenance action cards have equal sizes.
- Align picture-in-picture actions and reduce excessive inspector gaps.
- Show deletion errors in an accessible dialog above the sidebar. Referenced overlays remain protected; the dialog identifies the layouts or automation rules that must be changed before deletion, including disabled rules that retain references.
- Preserve the newer widget and navigation behavior from Stable 1.0.47.

## Optional application patches

Settings → Updates includes **Automatically install patches during scheduled restarts**, off by default. When enabled, compatible patches for the exact installed release are checked daily and installed at an enabled Live View restart schedule. A patch restarts the whole application, including the dashboard; the maintenance helper must be enabled and support patches.

Turning auto-install off preserves daily checks and **Install patch now**. Opting out during preparation prevents installer handoff. An installer already started cannot be canceled by changing this preference. Full version upgrades and channel switches still require confirmation; no schedule means no automatic patch installation.

Future patches use identities such as `1.0.48-beta.1-patch.1`, keeping the base release unchanged. Patch artifacts use the same verified installer packaging and publication checks, do not replace the advertised Stable release, and never appear as ordinary beta upgrades. The initial implementation still downloads a full installer; it does not hot-swap the dashboard or add transactional binary rollback. Streaming resolver updates retain their existing separate policy.

Install this beta normally to receive the updated Controller and maintenance helper. See [application patches](../application-patches.md) for scheduling, publisher instructions and verification limits.

## Validation

Release builds and isolated checks cover patch selection, exact-base compatibility, preference persistence, opting out during preparation, scheduler behavior, authentication/CSRF, verified service-worker installation with mocked host actions, and existing update-helper failure paths. Browser checks cover the new toggle, manual confirmation and the dashboard fixes. Tests use synthetic streams and packages; they do not install updates or restart a user's host. A real unattended patch upgrade on a disposable Windows installation remains a rollout validation item.
