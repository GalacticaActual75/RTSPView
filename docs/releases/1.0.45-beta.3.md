# RTSPView 1.0.45-beta.3

Fixes **Add weather** doing nothing when web administration is opened over ordinary LAN HTTP.

The layout editor used `crypto.randomUUID()`, which browsers expose on localhost and HTTPS but not ordinary HTTP network addresses. The button failed before it could open its full-grid choices. Layout and weather item IDs now use `crypto.getRandomValues()`, which works in the supported LAN HTTP environment.

The fix covers Add weather, both weather tile replacement paths, and creating standard or automation layouts. Existing settings and saved IDs are unchanged.

Validation includes reproducing the broken click over a real LAN HTTP address, verifying the fixed full-grid dialog and weather tile creation, and an automated regression test that removes `randomUUID` from the available browser APIs. The release workflow includes that regression test.

Update through **Settings → Updates → Beta**, then reload the web administration page. Stable remains v1.0.44.
