# RTSPView 1.0.46-beta.2

Based on 1.0.46-beta.1 and Stable 1.0.45. Settings remain schema 16. Stable is unchanged.

## Fixes and controls

- Fix #12: Restart Live View waits for the original process to exit before starting its replacement, avoiding a collision with the single-instance guard.
- Fix #13: MQTT separates current Viewer connectivity from the last failed delivery. Health recovery clears the current error while preserving failed-action history; probes never replay automations.
- Make the statistics preference control detailed Diagnostics statistics while retaining connection/stale-video alerts.
- Add named Windows monitor selection, resolution/primary labels and Identify. The previous numeric index remains a fallback.
- Expose the global hardware-decoding request under Advanced Display; changing it restarts affected native feeds. Composited picture-in-picture remains software decoded.

## Reliability and rendering

The installed logon runner supervises Controller with a handoff grace period and bounded retries. Log files have size/count limits; storage errors drop entries with diagnostic health reporting instead of terminating the application. Durable optional-state writes preserve valid backups and corrupted-file evidence; main settings recover from a valid backup when missing or malformed. Invalid restart schedules remain disabled, and authentication corruption does not silently reset credentials.

Each picture-in-picture overlay shares decoded frames with its original-source layout view, preserving independent framing. The largest synthetic wall has 48 views using 32 players. All-hidden consumers skip uploads. Native lifetime fixes guard retired sizing callbacks, synchronize snapshots with release, copy composited frames for snapshots and remove synchronous decoder-to-UI waits.

## Documentation

The README now covers complete packaging prerequisites, weather privacy/provider boundaries, periodic snapshots, automatic update discovery, framing, export/backup boundaries, audio behavior and terminology. Existing licensing rights are unchanged; no new open-source license is granted.

## Validation and remaining limits

The canonical regression suite and connector tests/build/package checks passed locally. After final native changes, the solution rebuilt with zero warnings/errors and native layout, UI and Viewer lifecycle checks passed again. Browser checks covered desktop and a 390-pixel viewport. The final 18-case [capacity matrix](1.0.46-beta.2-capacity.csv) passed with zero hidden uploads.

Earlier capacity attempts exposed intermittent native teardown failures; multiple full matrices passed after the lifetime changes. This does not establish long-duration stability. The fixture uses local 640×360 software video, not RTSP or hardware decoding. Main/overlay duplicate connections remain, and real GPU/codec/camera limits and 24–72 hour soak testing remain unqualified. Installed-host supervision/upgrade/rollback, physical monitor/DPI/touch and live integrations need field validation. Directly starting the executables does not start the external Controller supervisor.

See the [audit follow-up](../reviews/1.0.45-beta.3-follow-up.md) for the complete remaining work. Back up the private data directory before upgrading. Preserve data-protection keys during ordinary password recovery.
