# RTSPView 1.0.46-beta.4

Find ONVIF cameras from the stream editor, select a camera profile, and fill its
RTSP connection without guessing a URL. Discovery runs on the RTSPView host's
local network; manual addresses support cameras outside the discovery subnet.

- ONVIF Media/Media2, legacy capability lookup, WS-Security and HTTP Digest
  authentication, main/substream selection, and camera-clock adjustment.
- Source type help explains Auto and manual choices and links to provider lists.
- Fix the Streamlink/yt-dlp import-order conflict that prevented hostname-based
  media requests. Regression checks now include hostnames, not only loopback IPs.

See [ONVIF setup](../onvif.md) and [website sources](../website-streams.md).

## Validation and remaining limits

Automated ONVIF UDP and authenticated HTTP checks exercise simulated cameras,
including Media/Media2, clock skew, failure handling and credential encoding.
An ONVIF-selected RTSP stream is decoded by the real LibVLC player using synthetic
H.264 over RTP/TCP. Physical camera/firmware verification is still pending.
There is no universal claim of compatibility with all ONVIF devices or all sites
listed by Streamlink/yt-dlp. PTZ and ONVIF events are not included.

The reported YouTube Live source still returned HTTP 403 for media segments in
live testing after the library fix. YouTube playback is not claimed fixed.

The previously reported installer file-lock/partial-update issue is not repaired
in this release. If an in-app update fails, do not treat the displayed version as
proof of a complete installation. Close RTSPView and its supervisor before retrying
the downloaded installer. The requested updater redesign remains deferred.
