# RTSPView 1.0.44-beta.2

Custom overlays now follow the host camera image when switching layouts. Previously, overlay placement assumed Fit even when the host used Stretch, Fill, zoom or pan. This could leave a gap below a garage mask and extend it too far above the intended area in an uneven layout.

- Custom masks and their video now use the host camera's framing together, preserving the overlay's calibrated source crop. Rotated masks follow the same transform.
- Overlays are clipped at the host tile's edges. Standard picture-in-picture shapes keep their proportions and anchor to the actual picture edges.
- No new setting is needed. Existing custom masks use their 16:9 overlay-editor calibration; check placement once after updating.

Includes the 1.0.44-beta.1 additions: direct H100/H200 discovery for T110 door sensors, Open/Closed/Unavailable status, sensor-controlled overlays or saved layouts, and priorities on every MQTT/Tapo automation (1 is highest). Configure these in the Automation tab. See [Tapo setup](https://github.com/GalacticaActual75/RTSPView/blob/codex/beta/docs/tapo-automation.md).

Verified with geometry and actual WPF tile tests covering odd and portrait layouts, Fit/Fill/Stretch/Original, zoom/pan, rotated masks, bottom alignment and stable source crops, plus the native viewer regression suite. Physical Tapo hardware and the user's live camera alignment remain to be verified after installation. Stable remains 1.0.43.
