# RTSPView 1.0.46-beta.6

Streaming components now update automatically, separately from the application installer. After installing this beta once, RTSPView checks daily for tested, signed yt-dlp and Streamlink packages, without UAC or a restart. Settings → Updates shows component versions and update status.

Active streams keep running during updates. New streams use the latest validated package; a failed startup health check automatically falls back to the previous or bundled version. Download/signature failures retain the existing helper and retry the next day.

Website startup now shows “Opening website stream” instead of a stale-video warning. Explicit failures such as HTTP 403 take precedence over the missing-frame timer. Queued website requests share the same bounded startup deadline.

The reported YouTube live URL still has an unresolved HTTP 403 refusal. Updating dependencies automatically delivers future upstream fixes, but this release does not claim that playback issue is fixed.

Validation includes signed-package activation, signature/hash rejection, unsafe archive rejection, protocol compatibility, downgrade protection, rollback, live package leases, concurrent checks, download isolation, packaged helper health checks, and native synthetic RTSP/ONVIF/HLS/MP4 playback.
