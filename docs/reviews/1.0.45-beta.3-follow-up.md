# Follow-up to the 1.0.45-beta.3 implementation and product audit

Updated September 22, 2026 for 1.0.46-beta.2, following beta.1 (0202cc4). The original audit remains unchanged. Installed beta.1 does not include these follow-up fixes; update to beta.2.

## Included in beta.2

- **GitHub #12, Restart Live View:** the helper checks the original process identity and waits for its exit before launching one replacement. A real helper-process test holds the single-instance mutex through a four-second shutdown; intentional pause remains respected.
- **GitHub #13, MQTT acknowledgement banner:** bounded, non-mutating health probes separate current Viewer connectivity from historical delivery failure. Recovery clears the current error presentation without replaying an automation or erasing failed-action history.
- **Documentation:** complete Python/Tapo packaging prerequisites and canonical checks; weather request/privacy/cache and provider-use boundaries; browser-closed snapshots; automatic update discovery and cooldowns; Fit/Fill/Stretch claims; native versus web exports and private-backup boundaries; current terminology and licensing status. Basic product overview now precedes the long MQTT tutorial. Feedback and automation activity have appropriate locations. The README identifies unreleased behavior explicitly.
- **UI:** the former Show stream stats preference now controls detailed statistics in Diagnostics while retaining alerts. Settings offers named Windows displays, resolution/primary information and Identify, with the old index retained as a fallback. Advanced Display exposes the global hardware-decoding request; changing it recreates applicable native players. Software-composited overlays remain software decoded.
- **Reliability:** the installed logon runner supervises Controller with a handoff grace period and bounded retry backoff. Logs have a 4 MiB per-file limit, 14-file retention, bounded entries, storage-failure isolation and Controller log-health reporting. Optional state uses durable atomic writes, backups or safe defaults, and bounded private corruption evidence. Missing/malformed main settings recover from a valid backup. Invalid restart schedules stay disabled, and authentication corruption never silently resets credentials.
- **F07:** each picture-in-picture overlay and its original-source layout view share one decoder and bitmap, preserving independent framing. Hidden uploads stop only when all consumers are hidden. Queued sizing callbacks ignore retired/disposed players; native snapshot calls are synchronized with release, composited snapshots copy decoded frames, and decoder callbacks no longer wait synchronously for the UI. A largest-case wall of 48 views now uses 32 players rather than 48.

## Evidence and limits

The native capacity fixture covers 1/9/16 main views × 0/2/16 overlays × hidden/visible states. It uses local 640×360 software-decoded video, opens no RTSP connections and has one-second measurement windows. See [recorded capacity data](../releases/1.0.46-beta.2-capacity.csv). The largest case has 48 views and 32 players, with zero uploads for all-hidden presentation consumers. CPU/memory numbers are observations from this host, not supported production limits or a controlled before/after comparison.

The canonical suite passed, as did the Scrypted connector tests/build/package checks. After the final native lifetime changes, the complete solution rebuilt with zero warnings/errors and LayoutVisibility, Ui and ViewerLifecycle checks passed again. Regression coverage includes restart-helper lifetime, real MQTT/named-pipe health recovery, log retention/write failure/recovery, locked atomic writes, corrupt and missing-primary state recovery, Controller supervision/backoff, actual HTTP display preference persistence and older-client compatibility, native Diagnostics visibility, shared-frame visibility/framing/snapshots/disposal, and the existing canonical suite. Browser fixture checks cover desktop controls and a 390×844 viewport with no horizontal overflow and 44-pixel display-control targets.

Earlier capacity attempts exposed intermittent native teardown crashes. An initial sizing guard alone was insufficient. The final code also synchronizes native snapshot/release calls, copies composited frames for snapshots, avoids native sizing calls for WPF output, clears retired references and removes synchronous decoder-to-UI waits. Multiple complete matrices subsequently passed, including a final uninstrumented run. Regression tests cover queued sizing after disposal, capture during teardown and non-blocking decoder status callbacks. This is bounded evidence, not proof of long-duration native stability. The Y4M fixture can emit LibVLC demux-probing and unsupported window-control messages while its decoded-frame assertions pass.

## What still requires resolution or qualification

- Main/overlay and independently configured duplicate RTSP connections; warm/on-demand playback policy; production hardware/codec/bitrate capacity and a 24–72 hour representative RTSP soak with network failures, automation and snapshots.
- Real installer/logon supervision, service-assisted upgrade, rollback, reboot and disk-exhaustion testing on a disposable Windows host. The runner supervises Controller only when started by the installed logon task; direct/manual executable starts have no external Controller supervisor. Log writes remain synchronous and dropped entries cannot be reconstructed.
- Physical monitor identity/hotplug, mixed DPI, portrait layouts, touch and screen readers. Browser fixture checks do not qualify physical displays or decoder drivers.
- Physical Tapo devices/hubs, live Scrypted integration, real Open-Meteo outage/recovery and production multi-admin load.
- Saved weather locations, unified visibility explanations, a current Viewer-presentation strip, in-UI export boundaries, broader frontend initialization isolation and browser/native parity coverage.
- Runtime servicing/migration, installer signing and dependency inventory. Paid/custom weather endpoints are not implemented; changing a provider subscription alone does not change the endpoint used by the application.

Optional feature proposals such as main/substream failover, layout schedules, ONVIF, read-only operators, audio focus, external alerts and browser live video remain separate projects.
