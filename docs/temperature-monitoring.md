# Temperature monitoring

Overview → Detailed performance shows CPU and GPU temperatures. System → Viewer → Temperature monitoring shows the same current readings and lets the administrator save CPU/GPU warning limits in Celsius. The master “Show temperature warnings on the live view” switch disables all thermal warnings while retaining readings and limits. Individual CPU and GPU switches select which warnings are eligible. All warning switches default off. Limits initially contain 90 °C for CPU and 85 °C for GPU; these are editable starting values, not universal manufacturer limits.

The Controller samples supported sensors through LibreHardwareMonitorLib 0.9.6 every five seconds, independently of open browsers. Only CPU and GPU groups are enabled. Each reading is the highest valid temperature from that group across installed devices, including GPU hotspot/memory sensors when present. Missing or invalid readings are null/Unavailable. CPU access can require administrator privileges and an existing PawnIO installation. Hardware/driver support varies. RTSPView does not install a driver, alter security settings, or require elevation on startup. If driver availability changes, restart the Controller to rediscover hardware.

Enabled warnings appear in a smoked panel at the upper left of the native live wall when the current reading is strictly above its configured limit. Each device clears at or below its limit. Only the red text flashes slowly; the background stays solid. Windows reduced-animation settings produce steady red text. The panel stays inside the video area and is hidden for viewer configuration dialogs, minimization, and shutdown. No temperature-based restart or shutdown is performed.

The master switch and thresholds apply after Save temperature settings and reach the viewer on its next five-second refresh. Sensor failures clear the previous reading. The viewer rejects readings older than 20 seconds or more than five seconds in the future, preventing a stale warning when the Controller stops. HTTP status reads return null temperatures for stale data. A host-local `temperature-settings.json` retains warning preferences; `temperature-status.json` is an atomic, transient snapshot for the viewer. Portable configuration exports do not include these host-specific settings.

Authenticated GET/PUT `/api/temperatures` exposes the current readings and settings; PUT requires the existing CSRF token. `/api/telemetry` fills the existing CPU/GPU temperature fields from the cached sample, without additional hardware polling. Isolated tests use fake sensors and verify thresholds, toggles, stale/failed readings, persistence, API validation and authorization. The native visual test renders the actual warning window. Hardware access on the installed camera host remains to be verified before release.
