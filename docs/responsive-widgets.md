# Responsive widgets redesign

Implemented against RTSPView `origin/codex/beta` at `a9ed2d0`, on `codex/responsive-widgets`. Prepared for the 1.0.47-beta.13 release. Camera-host installation and real-feed acceptance remain separate.

## Audit and root causes

The audit followed options and validation in Core, settings normalization and backups, controller feed/cache services, layout editing and persistence, browser preview/Monitor rendering, and the native WPF wall.

- `WallWidget.ContentScaleFor` and its browser counterpart calculated a reference canvas from natural content height and then scaled it. Enlarging/resizing a tile changed effective text size without giving the content a useful view of its available space.
- Weather tried to shrink the main reading to retain optional content and then removed trailing rows. High/low priority depended on DOM/visual-tree order. The browser also maintained independent-widget CSS overrides separate from ordinary cards.
- Aircraft reserved a photo and attribution rectangle even when no valid photo metadata existed. Failed images were made invisible without releasing their layout space. This behavior intentionally froze text geometry but produced the reported blank areas.
- Aircraft fitting treated entire metric blocks as optional and gave registered owners priority over flight identifiers. It could discard altitude/distance together while retaining less useful identity details.
- Widget dialogs received output dimensions but no background camera. Thus their snapshot path, guarded by `backgroundSlot`, never ran for independent layout widgets.
- Adding streams, adding widgets, selection, content editing, and pixel positioning were split across several controls. Per-field typography sliders exposed renderer implementation details.

ADSB.lol selection, freshness expiry, units, aircraft rotation, provider cooldowns, trusted image-host validation, attributed exact/representative photo lookup, and cache isolation were already useful. These backend behaviors remain in place and were regression-tested with fake providers.

## Architecture

`WidgetViewport` in Core and `widget-responsive.js` define the same measured size contract: width, height, aspect category, padding, body/heading/reading typography, and information density. An executable parity check compares the browser values with values generated by native checks.

`WidgetFlow` is the native bounded priority layout. The browser's shared `fitRows` performs corresponding measured row removal. Optional content is removed as whole rows before primary information; neither renderer shrinks a complete reference canvas. Body text starts at 12 logical pixels and source credits at 10. Arbitrarily sub-text-sized legacy rectangles still cannot display meaningful text; containment remains enforced.

Weather cards at least 600×260 with a width/height ratio of at least 1.3 use two columns when temperature and supporting observations are selected. Temperature and condition occupy the left section; location, high/low, optional observations and attribution occupy the right. Body and reading typography grow with the tile rather than hitting the previous small caps. Each column independently drops lower-priority rows. Smaller or portrait cards keep the compact stack. Native and browser weather-specific sizing are included in the parity checks.

The same `WeatherView`/`AircraftView` serve all native placements. The same browser components serve dialogs, the layout canvas, and Monitor. WPF and HTML remain separate platform renderers: this is a shared sizing contract, not a claim of pixel-identical cross-platform rendering. Replacing WPF with an embedded browser would add runtime and native-video composition costs outside this redesign.

For a future widget, use the size contract, identify primary and optional rows, give loaded media and its credit a single priority group, and render through the same component in editor and wall contexts. Add the new type to validation, feed dispatch, and renderer dispatch; do not introduce a preview-only mock renderer.

## Editing and layout workflow

- One **Add content** menu exposes Camera stream, Weather, and Aircraft according to enabled plugins.
- New widgets start as grid tiles. Row/column anchors and spans follow weighted grid dimensions; keyboard arrows move and Shift+arrows resize. Edge dragging snaps grid widgets to cells. Orientation changes transpose widget anchors/spans.
- Existing floating placement remains intact. Users can switch between grid and floating placement. Floating presets stay visible; exact pixel geometry is under **Precise placement**.
- Selecting a widget opens its inspector; **Edit widget** or Enter opens the content dialog. Draft/save/apply behavior and undo/redo remain with the layout editor.
- Widgets retain their existing layer above cameras. Occupied cells do not implicitly delete or unassign a stream. The inspector explains this, and new widgets prefer empty cells when available.
- Dialog previews use actual target tile dimensions and the layout's camera snapshot composition, including grid proportions and basic camera fit/fill/stretch, alignment and zoom. They identify snapshots as snapshots and show an unavailable state for missing images.

## Weather

Temperature, high/low, condition and attribution have explicit priorities. Location, clock, metrics and forecasts appear as available space and density permit. Small, wide and tall cards retain readable primary readings. Cached weather continues aging during browser API outages instead of remaining visually fresh indefinitely. Loading, stale and unavailable states use the same bounded flow.

## Aircraft

The primary identifier, altitude and distance take precedence. Type, registration, speed, owner, route and other metrics receive progressively lower priorities. Small boards show one rotating flight; larger boards can show two. Existing nearest-first/stable 20-second rotation and unit conversion remain.

Images occupy space only after successful loading. Missing metadata, pending downloads and failures leave no photo rectangle. Loaded photos use contained aspect fitting; image and credit disappear together only when there is too little space for a usable image and its attribution. Loaded photos have a separate column beside the readings, or a separate row on tall cards; optional text cannot evict them. Photos scale to the available region with rounded image corners. Photo and ADS-B credits use a fixed 10px font. Minimal density controls text detail, not photo eligibility. Browser failures retry on a cooldown, as the native cache already does. Representative-photo labels and photographer/source/license attribution remain attached to the image.

## Settings and compatibility

Information density defaults to **Auto**, with Minimal, Standard and Detailed caps. Content fields, units, location, theme, accent, background opacity, alignment, photo visibility, filtering, hide-when-empty and fades remain. Aircraft presentation is one control: responsive card, photo emphasis, or two flights when space allows. Coordinates, altitude filters and advanced appearance use progressive disclosure.

Removed from the editor: individual aircraft text-size controls, text-size reset presets, icon size, padding, corner-radius sliders, and duplicate aircraft presentation/count controls. Legacy numeric fields remain deserializable and round-trip for compatibility, but no longer govern responsive text sizing. Legacy natural-height geometry still uses its existing formula so old floating placement is not unexpectedly moved.

Schema 21 adds optional grid `Cell` geometry and density defaults. Schema-20 widgets have no cell anchor and preserve their floating bounds. Existing earlier migrations still run. The first save of an older configuration creates `settings.json.before-responsive-widgets.json`; older binaries should use that backup rather than a schema-21 configuration. Settings revision checks, import validation, and sanitized export remain intact.

## Validation

- Release solution build: zero warnings/errors.
- ConfigurationChecks, WeatherChecks, AircraftChecks, and native UiChecks, including real WPF camera replacement and owned widget-window visibility/minimize/restore behavior.
- Native/browser size-contract parity; grid 1×1, 2×2, 3×3; weighted mixed cells; multiple row/column spans; grid shrink clamping; persistence and schema-20 rollback backup.
- Native aircraft matrix: 160×96, 180×400, 640×120, 320×180, 640×360, 960×540, 1920×1080; missing, pending, failed and loaded photos; long owner text; visible text containment; single/two-flight adaptation.
- Browser fixture: the same seven sizes for both widgets, fresh/empty/unavailable/loading/long-text feeds, failed/loaded/slow/tall images, and DOM bounds checks. Synthetic image responses use a localhost service worker; no external photo traffic is required.
- Integrated browser editor: selection, keyboard move/resize, draft apply, reload persistence, existing-widget edits, new-widget creation, loaded camera snapshot context, exact 640×720 preview for a resized tile, and 390px viewport containment.
- JavaScript selection/units/rotation tests, LAN HTTP layout creation/geometry tests, layout presets, modern dialog rules, preview refresh tests, syntax checks and whitespace checks.

Reproduce with `tools/checks.ps1`; its browser policy-parity check consumes the contract file generated by WeatherChecks. For visual review, run `node tests/responsive-widgets-fixture.cjs` (port 5212). For the full admin fixture, set `RTSPVIEW_WIDGET_FIXTURE=1` and run `node tests/layout-designer-fixture.cjs` (port 5097). Both fixtures use synthetic data and never control an installed wall.

## Remaining acceptance work

Validate on MAIN-CAM-MONITOR after an explicitly authorized install: real stream snapshots, GPU/native-video composition, real aircraft photo providers, monitor DPI and actual output resolution. Browser snapshots are not a live video capture and do not reproduce every native overlay/mask or original-resolution camera framing detail. The HTML/WPF typography and image timing can differ slightly despite matching size rules. The beta release packages this change; host installation and real-feed acceptance remain outstanding.

The sparse 1280×720 weather regression also checks that the temperature and high/low occupy opposite halves, remain visible, and scale their typography. The browser fixture includes Sparse weather and 1280×720 alongside its other sizes. Visual proof: `artifacts/widgets/weather-editor-balanced.png`; native proof: `artifacts/weather/large-weather-composition.png`.

Aircraft headings can be disabled per widget with Show location heading. The renderer removes the heading and its height reservation; existing settings default to showing it. Regression checks cover visibility, image area, rounded image clipping, fixed 10px credits, settings round-trip and reclaimed heading space.
